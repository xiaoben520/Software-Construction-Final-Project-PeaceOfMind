# 心安·MemoMind 系统设计文档

## 1. 系统概述

“心安·MemoMind”是一个基于 C# 和 WPF 的 Windows 桌面应用，面向大学生的学习与情绪支持场景。项目采用本地优先、模块可扩展的设计思路，核心目标是把任务管理、AI 聊天陪伴、文件工作区和个性化设置整合到一个统一界面中。

当前项目强调“页面可扩展、导航可配置、主页可组合”：

- 左侧导航栏用于切换页面，并可在设置中控制显示哪些页面。
- 主页以模块卡片方式呈现，可在设置中控制显示哪些模块。
- 新页面新增时，只需补充页面定义、视图模型和视图，即可快速接入主界面。

## 2. 总体架构

### 2.1 技术架构

- 表现层：WPF
- 架构模式：MVVM
- 核心层：业务接口、页面定义、通用状态与导航模型
- 基础设施层：SQLite、EF Core、本地配置、文件系统访问、AI 接入预留
- 测试层：单元测试与基础功能测试

### 2.2 分层说明

1. UI 层（MemoMind.App）
   - 负责页面展示、导航切换、命令绑定和样式资源。
   - 主要页面包括主页、任务看板、AI 聊天、文件工作区、设置页。

2. 核心层（MemoMind.Core）
   - 定义任务、文件工作区等领域接口与基础模型。
   - 统一业务规则，避免 UI 与数据库实现耦合。

3. 基础设施层（MemoMind.Infrastructure）
   - 负责 SQLite 数据访问、EF Core 迁移、本地存储、外部服务适配。

4. 测试层（MemoMind.Tests）
   - 验证任务增删改查、文件工作区、设置保存等关键流程。

## 3. 模块设计

### 3.1 页面与导航模块

系统采用“左侧导航栏 + 右侧内容区”的主界面布局：

- 左侧导航栏：展示当前启用的页面，如主页、任务看板、AI 聊天、文件工作区、设置。
- 右侧内容区：显示当前页面对应的视图内容。
- 主页：以卡片模块形式展示可跳转的功能入口。
- 设置页：支持配置左侧栏和主页中显示的页面。

页面接入规则：

1. 定义页面标识、标题、描述和默认可见性。
2. 注册对应的 ViewModel。
3. 通过内容模板或绑定机制自动显示对应视图。
4. 在设置页中勾选是否显示在左侧栏和主页。

### 3.2 任务看板模块

任务看板是当前项目的核心事务模块，用于管理学习、作业和待办事项。

功能包括：

- 新增任务
- 编辑任务
- 删除任务
- 任务状态管理（待办、进行中、已完成）
- 截止日期与优先级设置
- 按时间顺序展示任务列表

设计原则：

- 以“轻量任务清单”为主，不强制复杂项目管理能力。
- 后续若需要番茄钟、进度条或任务拆解，可作为扩展页面接入。

### 3.3 AI 聊天模块

AI 聊天模块用于提供陪伴式对话、学习建议和任务识别能力。

功能包括：

- 用户输入自然语言内容
- AI 返回回复、建议或结构化任务信息
- 支持将对话中提取出的待办事项转为任务
- 支持情绪安抚、学习鼓励和规划建议

设计原则：

- AI 功能可选启用；没有 API Key 时，基础应用仍可使用。
- AI 输出尽量采用结构化格式，方便后续扩展解析。

### 3.4 文件工作区模块

文件工作区用于管理学习资料、项目目录和常用文件路径。

功能包括：

- 保存文件夹或文件路径
- 管理常用工作区列表
- 一键打开文件或文件夹
- 记录最近访问时间

设计原则：

- 以本地路径为主，不依赖云同步。
- 允许用户快速建立课程资料和项目目录入口。

### 3.5 设置与扩展模块

设置页用于系统配置和页面开关管理。

功能包括：

- 保存 AI API Key
- 切换主题
- 配置提醒开关与基础偏好
- 控制左侧导航栏显示哪些页面
- 控制主页显示哪些模块

设计原则：

- 主页与导航不写死，页面展示由配置驱动。
- 后续新增“番茄钟”“赛博植物”等页面时，只需接入页面目录并在设置中勾选即可。

### 3.6 预留扩展模块

为保证项目后续可扩展，系统预留以下模块接入方式，但不作为当前核心必做内容：

- 番茄钟
- 赛博植物
- 周报统计
- 情绪曲线
- 其他个性化小组件

这些模块后续可通过新增页面定义、视图模型和视图的方式接入，不需要重构主窗口。

## 5. 核心流程设计

### 5.1 启动流程

1. 应用启动后读取本地设置。
2. 加载页面目录与可见性配置。
3. 初始化左侧导航栏和主页模块。
4. 进入默认页面。

### 5.2 页面切换流程

1. 用户点击左侧导航栏按钮。
2. 主窗口根据页面标识切换右侧内容。
3. 页面视图模型接管当前界面逻辑。

### 5.3 主页模块跳转流程

1. 主页以模块卡片展示可用页面。
2. 用户点击“打开模块”。
3. 系统跳转到对应页面。

### 5.4 设置保存流程

1. 用户在设置中修改主题、API Key 和页面可见性。
2. 系统保存通用设置与页面布局配置。
3. 左侧栏和主页模块立即更新。

### 5.5 任务管理流程

1. 用户新增或编辑任务。
2. 系统写入本地数据库。
3. 任务列表自动刷新。

### 5.6 AI 交互流程

1. 用户输入自然语言内容。
2. 系统拼接提示词并调用 AI 接口。
3. AI 返回建议或结构化结果。
4. 系统按结果更新任务或提示用户。

## 7. 接口与扩展约定

### 7.1 页面扩展约定

新增页面时建议遵循以下约定：

1. 在页面目录中注册页面定义。
2. 增加对应的 ViewModel。
3. 增加对应的 View。
4. 在设置页中默认允许用户选择是否显示。

### 7.2 数据访问约定

- 任务、文件工作区和设置数据全部优先本地存储。
- AI 对话历史和扩展模块数据采用“按需增加表”的方式处理。
- 非核心模块不要强行加入主数据库结构。

## 8. 角色分工落地方式

建议按模块分工，减少耦合和冲突：

- UI 负责同学：维护 `Views`、`ViewModels` 和样式资源。
- 业务负责同学：维护任务、聊天、导航与设置逻辑。
- 数据负责同学：维护实体、DbContext 和数据库迁移。
- 扩展负责同学：维护文件工作区、页面配置和后续新增模块。

## 9. 风险与对策

### 9.1 页面扩展后耦合度升高

**风险**：新增页面过多后，主窗口结构容易混乱。  
**对策**：统一通过页面目录和导航模型接入，不直接硬编码页面。

### 9.2 AI 接口不可用

**风险**：没有 API Key 或网络失败。  
**对策**：保留手动任务和基础页面功能，AI 作为可选增强能力。

### 9.3 数据结构过度膨胀

**风险**：把未来功能一次性写进数据库，导致项目臃肿。  
**对策**：核心表只保留当前必需数据，扩展功能按需添加。

## 10. 结论

当前版本的 MemoMind 采用“核心功能精简 + 页面可扩展 + 配置驱动导航”的设计方式，更适合课程作业和后续迭代。它既保留了任务管理、AI 聊天、文件工作区和设置这些核心能力，又为番茄钟、赛博植物等扩展页面预留了统一接入方式。

这种设计可以让项目在不重构主框架的前提下持续增加新功能，满足展示、分工和后续开发的需要。
- `GetAllTasks()`
- `AddTask()`
- `UpdateTask()`
- `DeleteTask()`
- `GetTasksByDate()`

### 7.3 文件接口

- `AddWorkspace()`
- `RemoveWorkspace()`
- `OpenWorkspace()`
- `ScanWorkspace()`

### 7.4 报告接口

- `GenerateWeeklyReport()`

## 8. 角色分工落地方式

建议将代码按以下方式分配：

- **UI 负责同学**：只改 `Views`、`ViewModels`、`Resources`、`Controls`。
- **AI 负责同学**：只改 `ChatService`、Prompt、DTO、解析逻辑。
- **数据库负责同学**：只改实体、DbContext、Repository、任务与日历逻辑。
- **文件与扩展负责同学**：只改工作区、设置、周报、提醒逻辑。

这样可以避免多人同时修改同一文件，降低冲突。

## 9. 风险与对策

### 9.1 AI 接口不可用

**风险**：没有 API Key 或网络失败。  
**对策**：提供无 AI 模式，保证基础功能可用。

### 9.2 任务自动识别不准确

**风险**：AI 输出不规范或识别偏差。  
**对策**：统一 JSON 输出格式，并增加校验与兜底提示。

### 9.3 团队协作冲突

**风险**：多人同时改界面或逻辑导致冲突。  
**对策**：先定义接口与目录，再按模块分工开发。

## 10. 结论

该系统适合采用“WPF + MVVM + SQLite + AI 服务”的架构。通过分层设计，可以让界面、AI、数据库和文件功能并行开发，同时兼顾课程作业的完整性与可展示性。
