# 心安·MemoMind C# 项目框架与分工

## 1. 项目定位

**项目名称**：心安·MemoMind  
**项目方向**：面向大学生的 AI 心理辅助与智能事务管理桌面系统  
**目标平台**：Windows 桌面端  
**建议技术栈**：C# + WPF + MVVM + SQLite + EF Core + HttpClient

### 1.1 项目核心目标

- 提供一个“能陪伴、能整理、能切换页面”的 Windows 桌面应用。
- 支持无 AI 模式下的基础任务管理、文件工作区与页面导航。
- 支持有 AI 模式下的自然语言任务提取、情绪识别与温和提醒。
- 形成“心理支持 + 事务管理”合一的轻量级桌面系统。

### 1.2 预期效果

- 用户能感受到系统可以帮助其梳理情绪与任务。
- 提升任务完成体验，降低页面切换与配置成本。
- 长期使用后形成稳定的学习与记录习惯。

---

## 2. 技术路线建议

### 2.1 UI 框架

建议采用 **WPF**，原因如下：

- 适合实现侧边栏、卡片式布局、圆角控件与现代桌面 UI。
- XAML 的数据绑定能力强，适合 MVVM 分层。
- 便于后续加入动画、主题切换和扩展页面。

### 2.2 架构模式

建议采用 **MVVM**：

- **Model**：负责数据实体，如任务、文件记录、设置、导航配置。
- **View**：负责界面展示，如主页、任务页、AI 聊天页、文件页、设置页。
- **ViewModel**：负责界面逻辑、命令绑定、数据刷新、状态管理。

### 2.3 数据与持久化

- **SQLite**：轻量本地数据库，适合课程设计与桌面应用。
- **EF Core**：简化 CRUD 与数据库迁移。
- **本地配置文件/数据库配置**：保存主题、API Key、导航开关、默认路径等。

### 2.4 AI 接入方式

- 使用 `HttpClient` 调用兼容 OpenAI 格式的 API。
- AI 功能做成可插拔模块：有 API Key 时启用，无 API Key 时系统仍可正常运行基础功能。
- AI 输出统一要求为结构化 JSON，便于解析成任务、情绪与建议。

## 3. 推荐项目结构

建议采用“解决方案 + 多项目分层”的结构，便于后续分工和提交。

```plaintext

│   │   ├── Commands              # 命令封装
│   │   └── App.xaml / MainWindow.xaml
│   │
│   ├── MemoMind.Core             # 核心业务层
│   │   ├── Interfaces            # 服务接口
│   │   ├── Models                # 领域模型
│   │   └── Helpers               # 通用工具
│   │
│   ├── MemoMind.Infrastructure   # 基础设施层
│   │   ├── Data                  # EF Core DbContext
│   │   ├── Services              # 数据与外部服务实现
│   │   └── Migrations            # 数据库迁移
│   │
│   └── MemoMind.Tests            # 单元测试项目
│
├── docs                          # 技术文档
│   ├── 需求分析报告.md
│   ├── 系统设计文档.md
│   ├── AI提示词设计方案.md
│   ├── C#大作业小组提案.md
│   └── 心安-MemoMind_CSharp项目框架与分工.md

```

### 3.1 目录设计思路

- `MemoMind.App`：只负责界面展示、导航和交互。
- `MemoMind.Core`：只放业务规则、接口、DTO 与通用逻辑。
- `MemoMind.Infrastructure`：负责数据库、AI、文件等底层实现。
- `MemoMind.Tests`：用于验证任务提取、数据处理和导航配置等关键功能。

## 4. 功能模块拆分

### 4.1 核心功能模块

1. **任务看板模块**
   - 任务新增、编辑、删除
   - 任务状态管理
   - 任务优先级
   - 任务完成度统计

2. **AI 聊天与任务提取模块**
   - 自然语言输入
   - 任务识别
   - 情绪识别
   - 自动生成待办事项

3. **文件工作区模块**
   - 保存常用文件路径
   - 快速打开文件/文件夹
   - 工作区列表管理
   - 文件变化刷新

4. **设置模块**
   - API Key 管理
   - 主题切换
   - 提醒设置
   - 默认路径设置
   - 左侧导航与主页模块配置

5. **扩展页面预留模块**
   - 番茄钟、赛博植物等后续扩展页面
   - 可通过页面目录和设置页开关接入

## 6. AI 功能实现思路

### 6.1 AI 输入输出规范

建议将 AI 输出统一要求为 JSON，例如：

```json
{
  "tasks": [
    {
      "title": "计网作业",
      "dueDate": "2026-04-23",
      "priority": "High"
    }
  ],
  "emotion": {
    "label": "烦",
    "score": 7
  },
  "suggestion": "先把作业拆成两步，再安排一个 25 分钟专注段。"
}
```

### 6.2 AI 处理流程

1. 用户输入自然语言文本。
2. 程序拼接 System Prompt 和 User Prompt。
3. 调用 AI 接口获取返回内容。
4. 将 JSON 反序列化为 DTO。
5. 自动写入任务或刷新聊天结果。
6. 在 UI 中同步刷新页面状态。

### 6.3 无 AI 兜底逻辑

如果没有 API Key 或网络不可用：

- 仍可使用手动新增任务。
- 仍可使用文件工作区和设置功能。
- AI 聊天区显示“当前未启用 AI 服务”的友好提示。

## 7. 4 人分工建议

建议采用“模块负责制”，每个人负责一个完整链路，避免只做零碎页面。

### 7.1 组长：架构与 AI 逻辑

**职责**：

- 负责项目整体架构设计与文件结构规划。
- 搭建 WPF + MVVM 基础框架。
- 设计 AI Prompt 模板与 JSON 输出格式。
- 实现 AI 请求、响应解析、任务提取逻辑。
- 汇总系统设计文档与接口文档。

### 7.2 成员 A：任务看板与导航

**职责**：

- 负责任务看板页面和任务增删改查。
- 负责主窗口左侧导航与右侧内容区切换。
- 负责页面可见性配置与主页模块展示。

### 7.3 成员 B：文件工作区与设置

**职责**：

- 负责文件工作区管理与快速打开功能。
- 负责设置页、主题切换、API Key 配置。
- 负责本地配置保存与恢复。

### 7.4 成员 C：测试与文档

**职责**：

- 负责测试用例整理与执行。
- 负责演示材料、答辩材料和文档汇总。
- 协助后续扩展页面的接入验证。

## 8. 结论

该项目适合采用“WPF + MVVM + SQLite + AI 服务”的架构。通过分层设计和页面可配置方案，可以让界面、AI、数据库和文件功能并行开发，同时兼顾课程作业的完整性与可展示性。
