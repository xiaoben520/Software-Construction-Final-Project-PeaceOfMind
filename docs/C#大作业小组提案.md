# 心安·MemoMind C#大作业小组提案

## 1. 项目内容

### 1.1 项目名称
心安·MemoMind：面向大学生的“心理陪伴 + 学习事务管理”桌面应用。

### 1.2 项目目标
开发一个基于 C# 的 Windows 桌面端应用，帮助用户在学习压力场景中完成以下目标：
- 管理任务看板、AI 对话和文件工作区；
- 通过左侧可配置导航与主页模块展示实现可扩展页面架构；
- 通过 AI 对话获得情绪安抚和任务拆解建议；
- 形成可持续的学习节奏与自我管理习惯。

### 1.3 技术方案
- 开发语言：C#（.NET 8）
- 前端框架：WPF（MVVM）
- 数据存储：SQLite + EF Core
- AI 接入：HttpClient 调用兼容 OpenAI 格式 API

---

## 2. 系统整体功能

系统按“核心功能 + 扩展预留”分为 6 个模块：

1. 主页总览模块
- 展示当前可用页面的快捷入口与简要状态。

2. 任务看板模块
- 新建/编辑/删除任务；
- 设置优先级、截止日期、完成状态；
- 按时间顺序展示任务。

3. AI 对话与任务提取模块
- 用户输入自然语言（如“我这周要赶三门作业”）；
- 系统提取可执行任务并写入任务列表；
- 识别情绪并给出温和建议。

4. 文件工作区模块
- 收藏课程资料、作业目录、项目文件夹；
- 一键打开常用路径；
- 支持最近使用记录。

5. 设置与扩展模块
- API Key 配置；
- 主题、提醒、默认路径设置；
- 本地配置持久化；
- 控制左侧导航栏与主页模块显示。

6. 预留扩展模块（可选）
- 番茄钟、赛博植物、周报统计、情绪曲线等；
- 通过新增页面定义、ViewModel、View 快速接入；
- 不需要重构主窗口。

## 3. 主要业务流程（含扩展规则）

### 3.1 主业务流程（学习任务闭环）

1. 用户录入需求
- 手动创建任务，或通过 AI 对话输入学习计划。

2. 系统结构化处理
- 将输入解析为任务项（标题、截止时间、优先级、备注）。

3. 制定执行计划
- 用户在任务看板中对任务进行优先级排序和状态管理。

4. 执行与记录
- 用户处理任务并在系统中更新状态；
- 后续扩展模块可接入专注记录、打卡或小组件能力。

5. 反馈与复盘
- 当日结束后可生成简要统计（完成任务数、情绪反馈、扩展模块数据）；
- AI 给出次日建议（先做高优先级、拆分大任务等）。

### 3.2 扩展激励规则（可选）

为提高持续使用率，系统保留轻量激励规则作为扩展能力：

1. 积分规则
- 当前版本不强制实现积分系统；
- 若后续加入赛博植物或打卡页面，可作为扩展玩法接入。

2. 连续打卡规则
- 可作为未来扩展模块，不作为当前核心验收项。

3. 等级规则（示例）
- 可作为扩展页面展示内容，当前版本保留设计即可，不强制实现。

4. 惩罚与容错规则
- 未完成计划任务不扣分，但系统提示“拆分任务难度”；
- 对逾期任务进行温和提醒，不做负向惩罚，避免压力叠加。

> 说明：扩展激励规则属于“软激励”，重点是鼓励持续学习，不制造额外焦虑。

### 3.3 页面配置流程（与系统设计文档一致）

1. 用户进入设置页，勾选左侧导航栏显示页面。  
2. 用户勾选主页模块显示页面。  
3. 系统实时更新左侧导航与主页卡片。  
4. 用户保存后写入本地配置，下次启动自动恢复。

## 4. 人员分工（4人）

> 可将“成员A/B/C/D”替换为真实姓名。

### 成员A（组长）：项目架构与导航框架
- 负责整体分层架构（App/Core/Infrastructure）与代码规范；
- 负责主窗口“左侧导航 + 右侧内容区”框架落地；
- 负责页面注册目录（可扩展页面接入机制）与联调推进；
- 交付：主框架可运行、页面切换稳定、新增页面可接入。

### 成员B：任务看板核心业务
- 负责任务看板页面（新增/编辑/删除/状态变更）；
- 负责任务优先级、截止时间、列表刷新等核心逻辑；
- 负责任务数据落库与基础校验；
- 交付：任务看板功能完整可演示，任务数据可持久化。

### 成员C：AI 对话与任务提取
- 负责 AI 对话页面交互与消息流转；
- 负责 Prompt 设计、结构化结果解析（任务/情绪/建议）；
- 负责“无 AI 模式”兜底提示与降级逻辑；
- 交付：AI 对话可用，任务提取链路可联调。

### 成员D：文件工作区、设置与文档测试
- 负责文件工作区（路径管理、快速打开、最近使用记录）；
- 负责设置页（主题、API Key、提醒、导航/主页模块显示配置）；
- 负责测试用例、演示脚本、答辩材料与文档汇总；
- 交付：设置项生效、工作区稳定、文档与测试材料齐全。

### 4.1 协作接口约定（避免分工脱节）
- A↔B：页面切换与任务页数据绑定接口统一；
- A↔C：AI 提取结果 DTO 与任务写入接口统一；
- A↔D：设置变更触发导航/主页实时刷新机制统一；
- B↔C：AI 提取任务写入任务看板字段（标题、优先级、截止时间）统一。

## 5. 时间进度安排（第9~12周，4.27—5.22）

| 周次 | 日期范围 | 里程碑目标 | 主要产出 |
|---|---|---|---|
| 第9周 | 4.27—5.3 | 需求冻结 + 架构搭建 | 用例清单、页面草图、项目骨架、数据初版 |
| 第10周 | 5.4—5.10 | 核心功能开发（任务/主页/设置） | 任务模块可用、导航可配置、基础数据落地 |
| 第11周 | 5.11—5.17 | AI 与文件工作区接入 + 联调 | AI 提取可用、文件工作区可用、模块联调版本 |
| 第12周 | 5.18—5.22 | 测试优化 + 文档答辩准备 | 可演示版本、测试报告、PPT 与答辩稿 |

### 每周检查机制
- 周一：确定本周目标与任务分配；
- 周三：中期同步与风险排查；
- 周五：功能验收与文档更新。

### 风险与应对
- AI 接口不稳定：保留无 AI 的手动流程兜底；
- 进度延迟：优先保证核心闭环（任务 + AI + 文件 + 设置）可演示；
- 联调冲突：统一接口命名与数据结构，提前进行集成测试。

## 结项验收标准（简版）
- 可完整演示“录入任务 → 管理任务 → 切换页面 → AI 对话/文件工作区”的主流程；
- 至少 4 个核心模块稳定运行（任务、AI、文件、设置/导航）；
- 文档齐全：需求、设计、测试、分工与进度记录。
